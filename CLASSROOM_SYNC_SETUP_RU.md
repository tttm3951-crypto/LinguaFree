# Автоматическая синхронизация LinguaFree 0.6 — настройка

## Текущий статус
В репозиторий добавлены клиент Android и серверный код Cloudflare Worker. **Автоматическая синхронизация пока не активна:** адрес сервера `ClassroomSync.ENDPOINT` пуст. Для запуска нужен Cloudflare-аккаунт, KV namespace и публикация Worker. Само добавление файлов в GitHub не создаёт сервер и не включает push.

## Развёртывание сервера
1. Создайте аккаунт Cloudflare и установите Node.js.
2. В каталоге `backend/cloudflare-worker` выполните `npx wrangler login`.
3. Создайте KV: `npx wrangler kv namespace create CLASSROOM_KV`.
4. Скопируйте выданный ID в `backend/cloudflare-worker/wrangler.toml` вместо `REPLACE_WITH_KV_NAMESPACE_ID`.
5. Выполните `npx wrangler deploy`. Убедитесь, что `https://<worker>.workers.dev/health` возвращает `{"ok":true}`.
6. Укажите опубликованный HTTPS URL в `app/src/main/java/org/linguafree/app/ClassroomSync.kt`, поле `ENDPOINT`, затем соберите APK через GitHub Actions.
7. В кабинете преподавателя нажмите «Создать кабинет и код подключения». Код действителен 24 часа. Передайте его ученику лично.
8. Ученик в «Мои достижения» вводит код и нажимает «Разрешить передачу прогресса».
9. При каждом открытии приложения ученика отправляется новый отчёт. Преподаватель получает обновления в открытом кабинете примерно раз в минуту и локальное уведомление о новом входе (если разрешены уведомления).

## Безопасность
- Без добровольного подключения сетевые запросы учебного прогресса не выполняются.
- Отправляются только имя/псевдоним, XP, пройденные уроки, результаты навыков, даты занятий; не передаются адрес, геолокация, контакты, фото или аудио.
- У ученика есть кнопка отзыва доступа, удаляющая запись на сервере. При отсутствии связи нужно повторить удаление позже.
- Кабинет и ученик получают отдельные криптографически случайные токены, доступ по HTTPS. Не передавайте токены третьим лицам.
- Код приглашения одноразовым **не является** и может подключать несколько учеников в течение 24 часов; храните его в секрете.
- Данные хранятся в Cloudflare KV до удаления; политика хранения и удаления должна быть утверждена до публичного релиза.
- В прототипе нет входа преподавателя по паролю и восстановления токена на новом устройстве; потеря данных приложения означает потерю доступа к кабинету.
- Обязательно настройте Cloudflare rate limiting, мониторинг и ограничения запросов до публичного запуска.

## Важно об уведомлениях
Текущая реализация проверяет сервер **только когда кабинет преподавателя открыт** (каждые 60 секунд). Уведомление на телефоне формируется после обнаружения нового входа. Настоящие фоновые push-уведомления при закрытом приложении потребуют Firebase Cloud Messaging (FCM), проекта Firebase, регистрации токенов устройств и отправки push из сервера. **FCM не настроен.**

## Ограничения тестирования
Автоматические проверки и успешная компиляция не заменяют проверку двух телефонов с разными аккаунтами. До реального запуска нужно проверить подключение, отзыв доступа, вход в приложение, выключенный интернет, восстановление после перезагрузки, права на уведомления, поведение после потери ключей и невозможность доступа к чужим данным.
